# v2.0.0 审核前 P0 验证清单

> 状态：提交微信审核前使用  
> 范围：只覆盖会影响 v2.0.0 审核与首批用户可用性的 P0 事项。

## 一、代码与配置检查

- [ ] `npm test` 全部通过。
- [ ] `npm run check-review` 通过；允许出现“订阅模板未配置”的 warning，但必须明确是否接受该降级。
- [ ] `miniprogram/config/env.js` 默认环境为 `production`。
- [ ] 微信公众平台已配置 `https://velo-rank-api.fly.dev` 为 request 合法域名。
- [ ] 微信公众平台已配置 `wss://velo-rank-api.fly.dev` 或对应 socket 合法域名。
- [ ] 服务类目已设置为体育赛事信息相关类目。
- [ ] 隐私保护接口已按微信后台要求配置。
- [ ] 订阅消息模板已在微信公众平台创建。
- [ ] 订阅消息模板 ID 已填入 `miniprogram/config/env.js` 的 `subscribeTemplateIds`。
- [ ] 后端生产环境已配置 `WECHAT_TEMPLATE_RACE_START`、`WECHAT_TEMPLATE_STAGE_END`、`WECHAT_TEMPLATE_RANK_CHANGE`、`WECHAT_TEMPLATE_KEY_EVENT` 中本次需要使用的模板。

## 二、体验版主路径验证

- [ ] 首次打开首页，无缓存状态加载正常。
- [ ] 首页赛事卡片可进入赛事详情。
- [ ] 赛事详情展示基础信息、赛段列表、领骑衫和各榜单入口。
- [ ] 赛段成绩页可展示排名、时间差、领骑衫信息。
- [ ] 分类榜 GC / 冲刺 / 爬坡 / 青年 / 车队榜可切换。
- [ ] 分类榜分页加载正常，无重复数据。
- [ ] 成绩行可跳转车手详情。
- [ ] 车手详情可展示基础资料、统计和历史成绩。
- [ ] 车队详情可展示基础资料、统计和车手列表。
- [ ] 搜索页可搜索赛事、车手、车队，并可跳转详情页。
- [ ] 赛事日历可按月展示赛事并跳转详情页。
- [ ] 赛事归档可按年份、类型、状态、关键词筛选。
- [ ] 推送设置可保存本地与服务端偏好。
- [ ] 订阅模板配置后，打开推送总开关能弹出微信订阅授权。
- [ ] 未配置订阅模板时，推送设置页明确提示“订阅模板待配置”，不误导为已可真实推送。

## 三、实时成绩验证

- [ ] 实时成绩页带 `raceId` 与 `stageId` 参数打开时能加载初始 GC 数据。
- [ ] WebSocket 连接成功后可收到 `welcome` 与 `subscribed` 消息。
- [ ] WebSocket 初始 `data` 消息能更新页面数据。
- [ ] WebSocket `update` 消息能更新页面数据。
- [ ] WebSocket 不可用时，页面能降级为 HTTP 轮询。
- [ ] 离开页面后 WebSocket 和轮询不会继续重复运行。

## 四、审核材料检查

- [ ] 小程序名称、图标、简介已确认。
- [ ] 隐私政策页面可访问，内容与当前能力一致。
- [ ] 用户协议页面可访问。
- [ ] 账号注销入口可访问，且有二次确认。
- [ ] 页面内没有“开发中”“TODO”“占位功能”等面向用户的文案。
- [ ] 管理员同步页不在普通用户入口中展示。
- [ ] 对外介绍不宣传 admin-sync、管理后台和数据导入脚本。

## 五、自动检查说明

当前仓库提供两个审核相关检查：

```bash
npm run check-review
npm test
```

`npm run check-review` 会检查小程序 AppID、隐私检查开关、默认生产环境、HTTPS/WSS 生产地址、隐私政策/用户协议页面、关键主路径页面和 admin-sync 不暴露在 tabBar 中。微信公众平台里的合法域名、服务类目、隐私接口和订阅消息模板仍需人工在后台确认。

## 六、提交前结论

全部 P0 项通过后再提交微信审核。若订阅消息模板暂时无法配置，本次仍可提交，但对外口径应改为“推送偏好设置已具备，真实订阅消息待微信模板配置后启用”。
