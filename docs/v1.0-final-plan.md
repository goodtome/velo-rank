### 第三部分：部署与运维加固（预计3天） ✅ 全部完成

线上环境已跑在 Fly.io(nrt)，256MB内存，基础可用但还需加固。

**3.1 日志系统（轻量版）** ✅ 已完成

不引入winston重型方案，用简单的结构化日志即可：

- 用 `console.log` + JSON格式输出（Fly.io会自动收集）
- 关键路由添加请求日志（method、path、耗时、状态码）
- 错误日志带stack trace
- 同步任务日志（成功/失败/耗时）

> 实现：requestLogger.js 提供 requestLogger（HTTP中间件）、taskLogger（脚本）、routeLog（路由级结构化日志）三个工具，全部路由和 WebSocket 已转换，auth.js token 泄露安全问题已修复。

**3.2 数据库自动备份** ✅ 已完成

PRD要求"每日自动备份"，当前没有备份脚本。简单方案：

- 写一个 `server/scripts/backup-db.js`，用 `mysqldump` 导出SQL文件
- Fly.io 上挂载一个 volume 存备份文件
- 用 cron 或 node-cron 每天凌晨跑一次
- 保留最近7天的备份，自动清理旧文件

> 实际方案：纯 Node.js 实现（无 mysqldump 依赖），批量读取 + gzip 压缩 + 7天轮转。实测：18表/31574行/1.3MB/1.7秒。Fly.io volume 和 Dockerfile 已配置。

**3.3 环境变量检查清单** ✅ 已完成

上线前确保生产环境的 `.env` / Fly secrets 配置正确：

- DB_HOST / DB_PASSWORD / DB_NAME（生产数据库）
- SESSION_SECRET（强随机字符串，不用默认值）
- CORS_ORIGINS（限制为小程序域名，不设为 `*`）
- 微信相关密钥（appid、secret等）

> 额外修复：发现并修复了 dotenv 路径不一致的关键 bug（app.js 和 database.js 加载路径均指向错误位置），增强 env-check.js 检查项（生产数据库、微信密钥占位符、管理员密钥、备份目录）。

**验收标准**: Fly.io上服务稳定运行，日志可查，数据库有每日备份。 ✅ 已达到
